# 十二項普通公會任務：集中驗收與正式安裝

版本 `20261104f`。十二項普通任務的場景、目標、戰鬥、防衛、護送、暫停續玩與可信重播已實作。本資料夾的測試均使用隔離記憶體角色；尚未安裝正式資料庫或部署正式 Edge Function。

## 集中驗收

開啟本機伺服器後，前往：

<http://localhost:8790/tools/guild-integration-preview.html?guild-missions=1>

1. 在頁頂「驗收任務」選擇任務。
2. 「重置測試角色並從頭出發」可完整遊玩；另外三個按鈕會用實際可重播的完整紀錄，還原首個互動、戰鬥後段或交付前的狀態。
3. 點地面／WASD／手機方向鍵行走，靠近名牌或目標後互動，停止三秒；移動、敵人攻擊會中斷。右側可下達集合、守點、撤退，或使用補給修復保護目標。
4. 完成任務後，走近該任務的金色交付點，按「完成並向公會交付」。採礦隊仍在港村公會門前報到。
5. 回到公會，按「批次交付成果」測試收據。切換任務前先按「暫停返回」。

頁面顯示「記憶體測試憑證／收據，非正式帳本」。測試不讀真實存檔、不連正式後端；重新載入或使用重置按鈕會重建測試角色。中途重播不代表正式票可快轉，正式結算另有真實時間下限。四項防衛需實際累積600秒遊戲時間，守護封印師遭敵人接近時暫停累積。

## 任務內容

| 任務 | 主要目標 | 可選目標 |
|---|---|---|
| 失聯採礦隊 | 調查紀錄、巨怪、至少兩名礦工撤離 | 三名礦工全存活，夥伴未倒地 |
| 毒霧藥草 | 六株藥草與蛛后 | 三個毒囊全部摧毀 |
| 商道清剿 | 三營地與強盜首領 | 救援斥候並讓其生還，揭露首領弱點 |
| 古墓封印 | 三封印各守護20秒、守墓者 | 各封印至少保留一半耐久 |
| 獵龍前哨 | 三前哨、幼龍、返回入口 | 三顆龍卵全摧毀，否則接戰時孵化 |
| 失落旗幟 | 持旗減速，從堡壘取回 | 不觸發警報，可在圈外解除警報繩 |
| 最後營火 | 守護補給營火10分鐘 | 營火耐久至少75% |
| 北境城門 | 守住兩路攻城10分鐘 | 攻城巨怪未命中城門 |
| 守護封印師 | 完成10分鐘有效施法 | 摧毀兩座遠程祭壇 |
| 難民撤離 | 接應三批15人，至少10人撤離 | 15人全部生還撤離 |
| 魔晶運輸車 | 隨行護車、擊退四路段伏兵至鍛爐 | 收集全部三個補給箱 |

普通模式沿用獨立戰術數值；尚未包含其他難度、正式裝備壓制、培養／商店、招募及其餘七種活動。怪物沿用既有原創巨蛛／強盜／巫妖／火龍動畫；任務物件與運輸車為原生繪圖，無新增商業素材。

## 正式安裝（由使用者操作）

1. 尚未安裝基礎公會時，先在 Supabase SQL Editor 執行 `tools/guild-system.sql`。
2. 執行本次新增的 `tools/guild-missions.sql`。可重跑，預設關閉任務簽票。全新安裝不需要先安裝首關的舊 SQL。
3. 建立名為 **guild-missions** 的 Edge Function，把本資料夾 **deploy.ts** 的完整內容貼入。這是單檔部署版本，不必逐檔新增 simulation.mjs；保留 JWT 驗證。服務金鑰只使用 Supabase 伺服器既有環境，不放進遊戲。
4. 確認部署成功後，由使用者執行：

```sql
update public.dragon_guild_mission_config set enabled=true where id=1;
```

5. 正式角色先完成雲端同步，再從村莊「公會接待員」／「傭兵公會」保存三人編隊、接取任務。查看公會公告可查詢已確認錢包與本週次數。

原先已安裝首關者，保留舊 **guild-lost-miners** Function 與舊資料表，讓原有憑證仍可交付；本次 SQL 會停止舊入口繼續簽票。新任務一律走新協定，無須修改或重跑 `guild-lost-miners.sql`。既有 SQL 檔與 `data/cloud.js` 均未修改。

## 帳本與紀錄

- 台北時間週一06:00重置。每週四次不同討伐、兩次不同防衛／護送計入任務冊；其他活動的每週次數未開放。
- 討伐：100聲望／10代幣／20徽章；防衛／護送：150／15／30。可選目標完成，代幣乘1.2。
- 同任務重打或超出次數：0聲望、代幣與徽章25%，向下取整。失敗不發獎、不扣任務冊次數。
- 未完成任務至本週重置失效；已完成紀錄可在票到期後24小時內交付，按簽票週別計入。
- 最多32筆未驗紀錄，每批依序交8筆，失敗即停並保留紀錄；同票同hash重送不會重複發獎。
- 成功與失敗紀錄都可交付。任務結束時仍倒地的夥伴療養30分鐘；途中救起的不需療養。首關舊協定保留舊倒地判定。
- 紀錄沿用原裝置的加密本機key與既有outbox，不增加player欄位／存檔schema。跨裝置請回原裝置交付。
- 可信端依票上的角色、編隊、種子與逐步輸入重播；不採信客戶端的成功／獎勵欄位。不能證明每個操作都由真人手動輸入。
- 聲望、代幣與徽章記入既有獨立伺服器錢包；尚未接消費商店，不直接改主遊戲金幣、裝備或個人傭兵。

## 開發檢查

```text
node tools/test-guild-missions.cjs
node tools/test-guild-missions-ui.cjs
node tools/test-guild-missions-db.cjs
node tools/prepare-guild-missions.cjs
node tools/test-guild-missions-verifier.mjs --deploy
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check.ps1
```

`prepare-guild-missions.cjs` 從正式核心與17景安全格產生 simulation.mjs、deploy.ts 與來源SHA256；修改共用核心後須重新產生，舊首關部署包亦用 `prepare-guild-verifier.cjs` 同步。test-proofs.json 是48場實走／重播測試中的法師完整紀錄，供集中驗收使用。verification.json 保存本機量測，不代表正式 Edge 平台效能保證。
